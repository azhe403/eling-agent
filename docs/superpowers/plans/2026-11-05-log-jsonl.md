# Log Format Toggle (text `.log` ↔ JSONL `.jsonl`) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a per-user `log.json` setting (format `text` | `jsonl`) that controls the backend log sink's formatter and file extension, with a dashboard control and live-rebuild on the dashboard host. MCP hosts pick it up at next session start.

**Architecture:** `LogFormat` enum drives a new `LogConfigStore` (Judge pattern, `RefreshIfStale` for cross-process) and a new `LogFormatForwardingSink` (stable DI sink wrapping a swappable inner `RollingDailyFileSink`). `LogsEndpoints` gains `GET/PUT /api/logs/config`; on PUT the dashboard host archives the old active file, swaps the inner sink, and reassigns `SerilogLog.Logger`. `ElingLoggingConfig.CreateSink` and `RollingDailyFileSink` gain a `LogFormat` parameter that picks formatter + date-regex at construction time. `LogReader` handles both extensions and JSONL `@lt` level tokens. `Logs.tsx` gets three JSONL-awareness patches.

**Tech Stack:** .NET 10, Serilog 4.4 (`Serilog.Formatting.Json.JsonFormatter` from core), ASP.NET Core minimal APIs, React (dashboard), xUnit.

**Spec:** `docs/superpowers/specs/2026-11-05-log-jsonl-design.md`

## Global Constraints

- .NET 10, Serilog 4.4.0 already in `Eling.Backend.csproj`; no new packages.
- `JsonFormatter` is in Serilog core (namespace `Serilog.Formatting.Json`); no `Serilog.Formatting.Compact` needed.
- `JsonNamingPolicy.CamelCase` + `JsonStringEnumConverter` are already configured for MVC/HTTP JSON options in `DashboardServices.cs` (lines 169-181), so endpoint request/response serialize enums as `"text"` / `"jsonl"` with no extra work.
- `SemanticJudgeStore` and `ToolPolicyStore` are the reference implementations for store pattern, including `FileStamp` record and `RefreshIfStale`.
- The frontend dev server runs on port 4427 and proxies `/api/*` to 4417; when it is running, never run `pnpm build` / `next build` — use `pnpm --filter eling-dashboard exec tsc --noEmit` for type checking.
- Commit policy: ask before committing; do not commit on your own initiative even when a step says "commit".

## Review Focus

These are the input classes and failure modes the spec implies but no task's tests exercise directly:

1. **Corrupt/unknown `format` value in `log.json`** (e.g. `"format": "xml"`): store resolves to `Text` (today's behavior), logs a warning, and the backend still starts. Owned by Task 2 (`LogConfigStoreTests`).
2. **Concurrent PUTs to `/api/logs/config` from two browser tabs**: the second PUT sees the first's write via `RefreshIfStale`-style stamp check on the config file, so last-write-wins without data loss. Owned by Task 2 (add a concurrent-update test).
3. **Switching format mid-day leaves the old active file stale**: the switch handler archives the old active file to `backend-{today}.{ext}` before starting the new one, so retention prunes it on schedule. Owned by Task 5 (`LogFormatForwardingSinkTests` or a new `LogFormatSwitchTests`).
4. **A session long enough that the user switches format while it is running**: that MCP host keeps its old format until the session ends; this is accepted, not a bug — no watcher. No test needed; document in the `log.json` template comment if one is added.
5. **A `backend.jsonl` file that is opened by a dashboard tail SSE while the host is mid-rebuild**: the tail endpoint resets position on file disappearance (`ReadNewLines` already handles this); the rebuild window is milliseconds. No test needed; the existing `ReadNewLines` shrink-reset logic covers it.

```csharp
public enum LogFormat { Text, Jsonl }

public static class LogFormatExtensions

    public static LogFormat Resolve(this LogFormat format, string? raw) =>
```

```csharp
public sealed class LogFormatForwardingSink : ILogEventSink, IDisposable
{
    private readonly object _gate = new();
    private RollingDailyFileSink? _inner;
    public RollingDailyFileSink? Inner { get { lock (_gate) return _inner; } }
    public void SetInner(RollingDailyFileSink? inner) { lock (_gate) _inner = inner; }
    public void Emit(LogEvent evt) { var i; lock (_gate) i = _inner; i?.Emit(evt); }
    public void Dispose() { var i; lock (_gate) { i = _inner; _inner = null; } i?.Dispose(); }
}
```
